# ADR 0025. Чужие сообщения можно удалять, но не править

- **Статус:** принято (этап P2, playtest-1)
- **Дата:** 2026-11-23
- **Связано:** ADR 0022 (чат через прокси, права `manage_messages`)

## Контекст

Этап 4.1 выдал Moderator и Admin право `manage_messages` и разрешил им и
удалять, и **править** чужие сообщения канала
(`server/internal/chat/chat.go`, `requireManage`). В ADR 0022 это записано
явно: «`manage_messages` в канале разрешает править и удалять чужие сообщения
канала».

На живом тесте 2026-11-22 у всех участников была роль Администратор, поэтому
любой мог открыть чужое сообщение и изменить его текст. Со стороны читателя
это выглядит как подлог: сообщение остаётся подписанным автором, а слова в нём
принадлежат модератору. Отметка «изменено» не говорит, кто именно правил.

Удаление — другое действие: оно не приписывает автору чужих слов, оно убирает
сообщение из канала целиком, и модерация без него невозможна.

## Решение

1. **Правка — только автор.** `Service.Edit` проверяет `requireOwn`: если
   `message.SenderID != userID`, возвращается `ErrPermissionDenied`. Право
   `manage_messages` на правку не влияет.
2. **Удаление — автор или `manage_messages`** в канале сообщения, как раньше
   (`requireManage`). В личных сообщениях модерации нет: удалить может только
   автор.
3. **UI скрывает недоступное, но ничего не решает.** `editable = own`,
   `deletable = own || canManage`. Сервер проверяет то же самое заново.
4. **HTTP API не меняется.** Правка и удаление идут только через control
   WebSocket (`EditMessage`, `DeleteMessage`); HTTP-эндпоинтов для них нет.
   `docs/api.md` описывает правило явно, чтобы не появлялось второй трактовки.

## Последствия

- Moderation workflow: модератор удаляет нарушающее сообщение, а не
  переписывает его. Если нужен «исправленный» текст, это новое сообщение от
  модератора, и оно видно как его собственное.
- Ломается только то поведение, которое и было ошибкой. Право
  `manage_messages` остаётся: удаление, модерация и будущие модераторские
  действия. Отдельного права «править чужие» не вводится: такого действия
  нет.
- Тесты: `server/internal/chat/chat_test.go` (модератор правит чужое →
  `ErrPermissionDenied`, удаляет → можно), интеграционный
  `server/internal/integration/chat_test.go` (то же через WebSocket),
  `client/ui/src/components/chat/MessageList.test.tsx` (у модератора нет
  кнопки правки на чужом сообщении, но есть кнопка удаления).
- Строка в ADR 0022 про правку чужих считается заменённой этим ADR; остальные
  решения 0022 (токен, прокси, вложения) действуют.

## Альтернативы

- **Оставить правку модератору, но подписывать «изменено модератором».**
  Требует нового поля в wire-формате и всё равно оставляет чужие слова под
  чужим ником. Отклонено.
- **Ввести отдельное право `edit_others_messages`.** Права, которое никто не
  просил и которое не описано в дизайне; расширяет поверхность прав без
  задачи. Отклонено.
