# ADR 0017. `--domain`: ACME через 80/443 и CapabilityBoundingSet

- **Статус:** принято (этап 6.1)
- **Дата:** 2026-11-21
- **Связано:** дизайн 4.3, 7; ADR 0001, 0015; `docs/INSTALL.md`

## Контекст

Дизайн 4.3 требует `--domain`: сертификат Let's Encrypt выпускается и
обновляется автоматически. Подпись задачи разрешает `certmagic` или `autocert`.
Сервер работает непривилегированным пользователем `rostalk` и слушает
управляющий порт 7443.

Let's Encrypt проверяет владение доменом только на портах 80 (HTTP-01) и
443 (TLS-ALPN-01). Ни `certmagic`, ни `autocert` не могут пройти проверку,
если эти порты закрыты. Вариант «выпускать сертификат вручную» противоречит
«автоматически», вариант «DNS-01» требует плагина под конкретного провайдера и
секретов DNS — лишняя зависимость для self-hosted продукта.

## Решение

1. В режиме `--domain` сервер поднимает два дополнительных слушателя:
   `:80` (HTTP-01 и редирект на HTTPS) и `:443` (TLS-ALPN-01). Управляющий
   порт остаётся 7443; ссылки-приглашения не содержат `fp` и указывают на
   `домен:7443` — клиент проверяет сертификат через Web PKI.
2. Сертификат и ключ ACME-аккаунта хранятся в `<данные>/acme` (0600), попадают
   в бэкап и не логируются.
3. Первый выпуск выполняется синхронно при старте с таймаутом 90 с. Ошибка
   содержит домен, порты, подсказку про DNS и предложение работать без
   `--domain`. Порт, который не удалось занять, даёт отдельную ошибку про
   `CAP_NET_BIND_SERVICE`.
4. `deploy/install.sh` пишет юнит с
   `AmbientCapabilities=CAP_NET_BIND_SERVICE` и
   `CapabilityBoundingSet=CAP_NET_BIND_SERVICE`, `NoNewPrivileges=true`,
   `ProtectSystem=strict`, `ReadWritePaths=<данные>`. Юнит не получает root.
5. Используется `golang.org/x/crypto/acme/autocert`: модуль `x/crypto` уже в
   зависимостях сервера, новых модулей нет. `certmagic` тянет `go-acme/lego` и
   цепочку плагинов, которые в 6.1 не нужны.
6. Адреса слушателей можно переопределить (`--acme-http-addr`,
   `--acme-tls-addr`), каталог ACME — для тестов
   (`ROSTALK_ACME_DIRECTORY`). Это не публичный контракт.

## Последствия

Плюсы: настоящий автоматический сертификат; ни одного нового модуля; сервис
остаётся непривилегированным, capability ограничена одним правом; отказ ACME
виден при старте, а не в первом TLS-рукопожатии клиента.

Минусы и компенсация:

- в режиме домена нужны 80/443; на VPS с reverse proxy их придётся освободить
  или не использовать `--domain` (тогда работает `fp`-режим). Это описано в
  `docs/INSTALL.md`;
- `--domain` не работает для IP-адреса и для машины за CGNAT без проброса
  80/443 — сообщение об ошибке предлагает `fp`-режим;
- healthcheck в Docker в режиме домена ходит на `https://<домен>:7443/healthz`
  (системные корни), поэтому DNS внутри контейнера должен разрешать домен.

## Откат

Убрать `--domain` из юнита/команды и перезапустить сервис: сервер снова
генерирует локальный CA и печатает ссылки с `fp`. Каталог `acme` можно удалить;
на базу и ключи идентичности это не влияет.
