# ADR 0029. DeepFilterNet3 как режим «Сильное» и выравнивание громкости собеседников

- **Статус:** принято (этап P17). Режим «Сильное» реализован и измерен, но **не включён в UI**: критерий «речь не страдает» не выполнен на фикстуре. Выравнивание громкости принято; по умолчанию включено с этапа P25 (ADR 0037).
- **Дата:** 2026-11-23
- **Связано:** ADR 0002 (голосовой движок, RED/DTX), 0013 (часы звука), 0014 (RNNoise, порядок обработки)

## Контекст

ADR 0014 поставил RNNoise (`nnnoiseless` 0.5.2): подавление пауз 20,2 дБ, задержка
+10 мс, 0,5 % ядра. На живой гарнитуре остаются жалобы на клавиатуру и вентилятор
в разговоре (не в паузах), а ADR 0014 прямо называл DeepFilterNet кандидатом, «если
понадобится». Этап P17 проверяет, можно ли дать третий режим «Сильное» без
ухудшения остального тракта, и добавляет опциональное выравнивание громкости
входящих голосов.

## Решение

### 1. Крейт

`deep_filter` на crates.io — версия 0.2.5 от 2022 года: это только обучающий код
(`libDF` без инференса и без модели), использовать его нельзя. Инференс DeepFilterNet3
есть в `deep_filter` из git-репозитория (tract + модель в `tar.gz`), но git-зависимость
нарушает правило «только стабильные версии». Опубликованные переработки инференса:

| Крейт | Версия | Лицензия | Зависимости | Модель | Задержка | Аллокации в `process` |
|---|---|---|---|---|---|---|
| `deep-filter-rt` | 0.2.0 (2026-11-07) | MIT OR Apache-2.0 | tract 0.23, ndarray 0.17, anyhow, itertools, realfft, rust-ini… | 3 ONNX, 8,0 МБ в .crate | 30 мс | да (ndarray/tract) |
| `dfn3_rs` | **0.1.2** (2026-11-12) | MIT OR Apache-2.0 | только `realfft` | пакованные веса, 5,26 МБ в секции `.dfn3` | 30 мс | **нет** (документировано) |

Выбран **`dfn3_rs` =0.1.2**: единственная прямая зависимость, чистый Rust, SIMD (AVX2/FMA/F16C)
с автоопределением и скалярным запасным путём, `process`/`reset` без аллокаций,
блокировок и ввода-вывода — то, что требует CONTRIBUTING.md для аудиопотока. Риск — крейт
молодой (299 загрузок, один автор, 14 `unsafe`-блоков в SIMD-ядрах). Снижение риска:
выход `dfn3_rs` сверен с `deep-filter-rt`, портом исходного кода DeepFilterNet,
на речи с шумом (корреляция 1,0000 при нулевом сдвиге, одинаковые 30 мс задержки;
см. «Замеры»). Версия закреплена `=0.1.2`; замена на `deep-filter-rt` не меняет
API ядра: `DeepFilter` — единственная точка использования.

Лицензия весов: DeepFilterNet — MIT OR Apache-2.0, README апстрима подтверждает, что
веса лицензированы так же (коммит `7b14b89`, 2026-11-06). Тексты — в крейте.

## Замеры

Фикстура: `tools/audio-fixtures` (речь SAPI 48 кГц) + розовый шум −45 dBFS +
щелчки клавиатуры −20 dBFS, как в ADR 0014. Тест
`deepfilter_beats_rnnoise_on_keyboard_and_fan_without_eating_speech`
(`make test-voice-quality`), цепочка `ApmProcessor` офлайн, HPF включён, AEC и AGC выключены.

| | WebRTC NS | RNNoise | DeepFilterNet3 |
|---|---|---|---|
| Подавление пауз | 14,0 дБ | 20,8 дБ | **39,4 дБ** |
| Речь к чистой | −0,6 дБ | −0,4 дБ | **−7,0 дБ** |
| Задержка стадии | 6,9 мс | 10,9 мс | 30,9 мс (чистая стадия: 30,0 мс, `deepfilter_stage_delay_is_within_forty_milliseconds`) |
| CPU на кадр 10 мс, release (отдельный бенчмарк, 10,9 с аудио, этот ПК) | не измерено отдельно (внутри libwebrtc) | 64 мкс (0,64 %) | 374 мкс (**3,7 %** ядра) |
| CPU, debug-тест с оптимизированными зависимостями, финальный прогон 2026-11-24 | — | — | 125 мкс в среднем (1,25 %), 0,37 с на 30 с аудио, худший кадр 2189 мкс |
| Размер .exe | см. отчёт этапа | | +весы 5,26 МБ (секция `.dfn3`) |

Финальная приёмка 2026-11-24 (после слияния `main` с P9/P10/P13/P15): `make test-voice-quality`
— 19 из 19 тестов, 0 падений, 470,5 с. Тест под нагрузкой
(`deepfilter_survives_cpu_load_without_underruns`) напечатал `publish_underruns 0` и остальные
счётчики по нулям и для контроля RNNoise, и для DeepFilterNet3; переключение моделей на лету —
0 разрывов. Размер release-клиента `rostalk.exe`: **56 018 432 байта (56,0 МБ / 53,4 МиБ)**,
в том числе 5,26 МБ весов. Цифра меньше WIP-оценки 57,35 МБ из handoff: та мерилась до слияния
`main` и другим способом; актуальна измеренная здесь.

Сверка независимой реализации: `dfn3_rs` и `deep-filter-rt` (порт апстрима на tract) на одном
входе дали корреляцию 1,0000 при нулевом сдвиге. `deep-filter-rt` при этом стоит 1940 мкс на кадр
(19,4 % ядра) и аллоцирует в `process`, поэтому не подходит для аудиопотока.

Под нагрузкой (2 процесса-пожирателя ядер, 60 с, AEC + DeepFilterNet3): тест
`deepfilter_survives_cpu_load_without_underruns` печатает счётчики с контролем RNNoise;
в финальном прогоне 2026-11-24 у обоих `publish_underruns 0`, `capture_underruns 0`,
`playback_underruns 0`, `mixer_underruns 0`, `apm_errors 0`.

## Критерии включения режима и вердикт

| Критерий | Итог |
|---|---|
| Кадр 10 мс в реальном времени с запасом | выполнен: 3,7 % ядра, запас ×27 |
| Задержка не больше 40 мс | выполнен: 30 мс |
| Паузы лучше RNNoise | выполнен: 39,4 против 20,8 дБ |
| Речь не страдает (не хуже −3 дБ) | **не выполнен: −7,0 дБ** на речи SAPI |

Вердикт: режим **не включается** в настройки. Причина записана честно: на синтетическом
голосе SAPI DeepFilterNet3 заметно давит и речь. Возможно, на живом голосе картина другая
(SAPI монотонен и частично похож на шум), но подтвердить это можно только A/B на живой
гарнитуре владельца (G6). Код стадии, `NoiseModel::DeepFilter`, переключение на лету и
тесты оставлены; пункт в `SettingsDialog` убран. Чтобы включить: добавить `<option
value="deepFilter">` и строку `voice.noise.deepFilter` в i18n после A/B. Гейт по VAD для
этого режима не реализован: `vad()` возвращает `None`, гейт смотрит только на уровень.

## Переключение на лету

`set_processing` создаёт новый `ApmProcessor` на управляющем потоке (там же прогрев модели:
8 кадров, `reset`, пороги по умолчанию), капчер-поток подменяет его между кадрами; тракт и
комната не перезапускаются. Тест `the_noise_model_switches_on_the_fly_without_gaps`: Off, WebRTC,
RNNoise, DeepFilterNet3 по кругу, 0 ошибок APM, 0 разрывов публикации. Освобождение старого
процессора идёт на капчер-потоке (как и для RNNoise в ADR 0014).

## Выравнивание громкости собеседников

`crates/voice/src/leveler.rs`, по одному `Leveler` на дорожку внутри `Mixer`, после измерителей
уровня и до пользовательской громкости. Оценка уровня речи (RMS, атака 0,5 с, спад 2,5 с;
кадры тише −50 dBFS не учитываются), цель −22 dBFS, усиление в пределах ±12 дБ, скорость
+3/−10 дБ/с, пиковый лимитер −1 dBFS (мгновенное снижение, возврат ~0,2 с, быстрая линейная
рампа 1 мс, жёсткий потолок на выходе). Выключение возвращает усиление к 0 дБ со скоростью
30 дБ/с без щелчка; без состояния буферов, без аллокаций. Настройка
`voice.levelVoices` (с P25 по умолчанию `true`, см. ADR 0037), переключается на лету через
`update_settings`.
Индикатор «говорит» и уровень в UI считаются до выравнивания.
Событийные звуки P10 добавляются в кадр после `Mixer::mix` (`sounds.mix_into` в
`playback_loop`), поэтому выравнивание их не трогает: громкость сигнала не зависит от
усиления голоса. Это закреплено тестом
`leveling_changes_the_voice_but_not_the_event_sounds` (сравнение амплитуды сигнала при
включённом и выключенном выравнивании, допуск 1 LSB на усечение в `i16`).

## RED и DTX (п. 3 этапа)

`voice_publish_options` (`engine.rs`): `red: true`, `dtx: !stereo`, `audio_encoding.max_bitrate`;
сервер разрешает `audio/red` по умолчанию (livekit-server v1.13.11, `pkg/config/config.go:628`,
наша конфигурация список не переопределяет). Через SDK (`livekit` 0.12, `TrackPublishOptions`)
настраиваются только верхний битрейт, DTX, RED, источник; inband FEC, длина кадра Opus и
сложность кодека API не имеют (ADR 0002). Юнит-тесты фиксируют RED и DTX для голоса, RED без
DTX для музыки.

## Последствия

- Плюс: готовая, измеренная стадия и тесты; решение о включении опирается на A/B владельца.
- Плюс: выравнивание громкости доступно; с P25 включено по умолчанию и не трогает звук стрима
  (ADR 0037).
- Минус: молодой крейт `dfn3_rs` (299 загрузок, один автор, `unsafe` в SIMD); на CPU без
  AVX2/FMA/F16C он идёт скалярным путём, который не измерен.
- Минус: +5,3 МБ к exe, пока режим не включён, выгоды нет. Если после A/B режим не нужен,
  откат: удалить `deepfilter.rs`, зависимость и `NoiseModel::DeepFilter`.
- `[profile.dev.package.dfn3_rs|realfft|rustfft] opt-level = 3` — только чтобы debug-гейт
  качества мог работать в реальном времени; release не затронут.
