# 0010. Закрытие окна: трей, а не выход

**Статус:** принято (этап 2.4)
**Дата:** 2026-11-20

## Контекст

В 2.1 у клиента появился трей (`Show`/`Quit`) и один экземпляр приложения. В
2.3 ядро получает голосовой движок, который должен работать без окна. Раздел 5.5
дизайна («экономный режим») описывает уничтожение WebView через N минут после
сворачивания, но этот этап в 2.4 не реализуется.

Пока поведение не зафиксировано, крестик окна либо убивает голосовую сессию,
либо молча оставляет пользователя без окна — оба варианта неочевидны.

## Решение

- Настройка `closeToTray` в ядре, по умолчанию **включена**.
- Включена: `CloseRequested` отменяется, окно скрывается в трей. Ядро,
  соединение, голос и горячие клавиши продолжают работать. Трей и повторный
  запуск (single instance) возвращают окно.
- Выключена: крестик завершает клиент (`app.exit`), как обычное приложение.
- Пункт трея `Quit`/`Выйти` завершает клиент всегда, независимо от настройки.
- Окно не уничтожается: WebView остаётся в памяти (экономный режим 5.5 не
  реализован). Это осознанный компромисс до 5.5; бюджеты памяти из раздела 6
  дизайна для свёрнутого окна пока не достигаются.
- Строки трея локализованы (`ru`/`en`) и перестраиваются при смене языка.

## Последствия

- Пользователь не теряет голосовую сессию от случайного закрытия окна.
- Клиент остаётся в трее и после перезапуска окна получает снимок состояния из
  ядра, а не восстанавливает UI-состояние.
- Текущее потребление памяти в свёрнутом состоянии — как у открытого окна;
  уменьшение появится вместе с 5.5.
- Тест «второй запуск показывает окно» остаётся ручным: single instance и трей
  не проверяются в jsdom.
