# ADR 0012. Ввод для PTT, совместимый с Vanguard

- **Статус:** принято в `stage/2.3.1b-controls` @ `563a250`, влито в
  `stage/2.3-voice-engine` @ `9c3c028`; живая проверка Vanguard — гейт G7,
  ещё открыт
- **Дата:** 2026-11-20
- **Связано:** дизайн 5.2, ADR 0002, ADR 0011

## Контекст

Поддержка Vanguard (Valorant) обязательна. Vanguard — kernel-level античит,
который может блокировать или считать подозрительными глобальные хуки ввода,
инъекции в процесс игры и оверлеи. PTT в первой версии 2.3.1b использовал
`WH_KEYBOARD_LL`/`WH_MOUSE_LL`, а по умолчанию биндил обычную клавишу `V`.
Это одновременно:

- UX-баг: набор `V` в игре/чате открывает микрофон;
- риск для античита: глобальный keyboard hook видит все нажатия, а
  printable-клавиша как PTT выглядит особенно подозрительно.

Нельзя гарантировать совместимость с Vanguard только обещанием «мы не
инжектимся»: политика античита закрыта и меняется. Нужен минимально инвазивный
путь и обязательная проверка на живом клиенте.

## Реализация в 2.3.1b

- `client/src-tauri/crates/platform/src/hotkey.rs`: `RegisterRawInputDevices`
  + `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY` на message-only окне, разбор `WM_INPUT`;
  никаких `SetWindowsHookEx`. По умолчанию регистрируется только мышь (X1/X2);
  клавиатура — только при явной клавише, чтобы не держать фоновый захват всех
  клавиш.
- `client/src-tauri/src/ptt.rs`: по умолчанию X1/X2; `ROSTALK_PTT_KEY` —
  явная отладочная клавиша, не printable-дефолт.
- Регрессионный тест запрещает вернуть `SetWindowsHookEx`/`WH_*` в модуль.
- `make check` и release-сборка зелёные; exe запускается при работающем
  драйвере Vanguard. Probe получил X1/X2 при запущенном Valorant; живой голос
  в игре — ещё нет (G7).

## Решение

1. **Основной путь PTT — Raw Input**:
   - `RegisterRawInputDevices` с `RIDEV_INPUTSINK` на скрытом message-only окне;
   - клавиатура и кнопки мыши X1/X2 приходят как `WM_INPUT`;
   - никакого `SetWindowsHookEx`, инъекции, чтения памяти игры, драйвера или
     повышения прав;
   - обработка только ставит флаг PTT; ввод не подавляется.
2. **Клавиатурный fallback — `RegisterHotKey`** (без хука), если Raw Input
   недоступен/не подходит. Привязка задаётся пользователем; printable-клавиша
   не является глобальным дефолтом.
3. **По умолчанию — только X1/X2.** Клавиша — явная настройка 2.4 или
   `ROSTALK_PTT_KEY` для отладки, не `V`.
4. **`WH_KEYBOARD_LL`/`WH_MOUSE_LL`** — только opt-in fallback для отладки,
   не дефолт и не то, что мы обещаем в Vanguard. **Отменено обновлением ниже:
   хуки запрещены полностью.**
5. **Оверлей** — отдельное прозрачное always-on-top окно, без инъекции в игру.
   В Vanguard/exclusive fullscreen его видимость не гарантируется; это
   отдельный ADR/спайк, не часть PTT.
6. **Гигиена античита:** без kernel-драйвера, без auto-elevation, без
   обфускации/скрытия процесса, без чтения памяти игры, без DLL-инъекций.
   Код-сигнинг релиза — 6.2. Vanguard не обходим и не «обманываем».

## Обязательный спайк и гейт G7

Проверить на Windows 11 с работающим Vanguard/Valorant:

- RosTalk запущен до игры и после игры;
- PTT X1/X2 через Raw Input, клавиатурный fallback через `RegisterHotKey`;
- голос в фоне, окно свёрнуто/в трее;
- Vanguard не блокирует ввод и не завершает RosTalk;
- отдельное always-on-top окно (если проверяем оверлей) — видно/не видно,
  без инъекции;
- журнал: нет токенов/ключей; нет попыток открыть процесс игры.

Если Raw Input блокируется, честно зафиксировать: PTT в Vanguard не
поддерживается, предложить внешнее HID-устройство или ручной выбор другого
пути. Не считать «не проверили» совместимостью.

## Последствия

- 2.3.1b нельзя вливать с глобальным `V` и без спайка Vanguard.
- Raw Input требует скрытого окна и message pump; это отдельный модуль
  `crates/platform`, PTT-логика остаётся тестируемой.
- `RegisterHotKey` не покрывает боковые кнопки мыши; Raw Input покрывает.
- Оверлей в Vanguard, скорее всего, не будет работать без официальной
  интеграции; это не блокирует голос.

## Альтернативы

- **Оставить WH_* hooks.** Проще, но риск блокировки/флага и глобальный `V`.
  Отклонено как дефолт.
- **Только RegisterHotKey.** Меньше риска, но нет мышиных кнопок и возможны
  конфликты с игрой.
- **Внешний HID/foot pedal.** Не требует хуков, но отдельное железо; запасной
  вариант, не MVP.
- **Инъекция/оверлей в игру.** Запрещено: античит и безопасность.

## Обновление 2026-11-26 (P24)

- Регистрация Raw Input теперь переустанавливается при смене привязки: обработчик
  и поток сообщений освобождаются вместе с регистрацией. До этого второй
  `install` в процессе падал с «only one global input registration is
  supported», и PTT умирал до перезапуска.
- Через тот же Raw Input идут не только PTT, но и переключатели микрофона и
  звука. Одиночная клавиша или кнопка мыши работает в фоне сразу; сочетание с
  `Ctrl`/`Shift`/`Alt` — только после явного переключателя «Сочетания в фоне».
  По умолчанию он выключен, поэтому свежая установка остаётся mouse-only, как
  требует этот ADR. Модификаторы считаются по make/break-событиям Raw Input, без
  `GetAsyncKeyState`; фоновая регистрация клавиатуры включается только явной
  одиночной клавишей или этим переключателем.
- PTT — удержание: гейт открыт, пока удерживается хотя бы один привязанный
  ввод, и закрывается на отпускании последнего, в том числе при отпускании
  любого модификатора из сочетания. Удержание создаёт только первый make
  основной клавиши; raw auto-repeat после нажатия модификаторов не открывает
  PTT, а отпускание модификатора удаляет недействительное удержание, поэтому
  повторное нажатие модификатора без нового make основной клавиши не
  возобновляет передачу. Переключатели срабатывают один раз на осознанное
  нажатие, авто-повтор игнорируется.
- `WM_INPUT_DEVICE_CHANGE` (`GIDC_REMOVAL`) снимает удержание только с
  исчезнувшего устройства. Отключение второй мыши не закрывает PTT на первой и
  не даёт авто-повтору первой переключить mute второй раз; состояние хранится
  по `RAWINPUTHEADER.hDevice`.
- Доступность PTT, mute и deafen независима: невалидное сочетание PTT или
  занятые боковые кнопки не отключают валидные переключатели. UI получает
  отдельный статус по каждому действию, а не один флаг PTT.
- Переключатели применяются через общее сохранённое состояние
  (`VoicePreferences`, которое обновляется после успеха и ручной кнопкой, и
  хоткеем) и сериализуются с ручной кнопкой. Два быстрых нажатия переключают
  состояние дважды даже без server echo; действие, поставленное в очередь в
  прежней сессии, отбрасывается после смены канала или переподключения.
- Явная привязка переключателя на `Mouse4`/`Mouse5` забирает эту кнопку у
  неявной пары PTT; PTT сохраняет вторую кнопку. Явная привязка PTT на одну
  боковую кнопку не добавляет вторую; клавиша по-прежнему работает вместе со
  свободными боковыми кнопками.
- Если PTT назначен на сочетание без переключателя «Сочетания в фоне»,
  глобальный слой не притворяется, что сработала пара X1/X2: статус
  `Unavailable` и текст ошибки видны в интерфейсе. С включённым переключателем
  сочетание работает в фоне.
