# ADR 0034. Публичный репозиторий, лицензия MIT и подпись кода

- **Статус:** принято (этап P20, решения владельца от 2026-11-25)
- **Дата:** 2026-11-25
- **Связано:** ADR 0015 (локальная сборка без CI), ADR 0026 (GitHub Releases),
  ADR 0033 (переименование)

## Контекст

Проект открывается: код и релизы публикуются в
`github.com/v4dikos1/RosTalk`. В рабочем репозитории есть то, что публиковать
нельзя или незачем: инструкции и промпты для агентов, журнал приёмки,
скриншоты и логи с реальных машин, адрес реального сервера, личные пути
машины сборки, прототипы этапа 0. В истории из ~480 коммитов эти данные есть
и в старых версиях файлов. Лицензии у проекта не было, а без неё код
формально не открыт. Релизы до 0.2.0 жили в приватном репозитории, поэтому
апдейтер и `install.sh` не могли работать для посторонних.

## Решение

1. **Два репозитория.** Рабочий остаётся приватным и единственным местом
   разработки. Публичный получает снимки: один коммит на релиз (или на
   заметное обновление), без приватной истории. Переписывать историю
   (`filter-repo`) не стали: секрет из удалённого или переименованного файла
   легко пропустить, а после публикации его не вернуть.
2. **Экспорт** — `tools/public-export/export.sh` (сам инструмент приватный):
   - берёт дерево коммита через `git archive`, поэтому неотслеживаемые,
     игнорируемые и незакоммиченные файлы не попадают никогда;
   - удаляет пути из `exclude.txt`: инструкции агентов, журнал и регламент ревью,
     план этапов, handoff, `docs/assets/`, `docs/security/`, `docs/ux/`,
     живые чек-листы, `spikes/`, `.github/workflows/` и сам инструмент;
   - сканирует результат: шаблоны `scrub.txt` (ключи, токены, адрес сервера,
     личные пути и имена, имя приватного репозитория, следы агентов), e-mail
     вне белого списка, файлы больше 5 МБ. Любое совпадение останавливает
     экспорт до записи в публичный клон;
   - заменяет рабочее дерево клона публичного репозитория и делает коммит
     только с `COMMIT=1`. **Push всегда делает человек** после просмотра.
3. **Публичные файлы живут в рабочем репозитории.** `README.md`
   (английский) и `README.ru.md`, `LICENSE`, `CONTRIBUTING.md`, `SECURITY.md`,
   `THIRD_PARTY_NOTICES.md`, `docs/DEVELOPMENT.md`, шаблоны issue/PR. Правила
   разработки перенесены из инструкций агентов в `CONTRIBUTING.md`; политика
   античит-гигиены — из плана в `docs/anticheat.md`. Инструкции агентов
   теперь описывают только их процесс и ссылаются на эти файлы. Ссылки в коде
   ведут на публичные документы. ADR не переписываются: `docs/adr/README.md`
   объясняет, что упомянутые в них прототипы и журналы не публикуются.
4. **Лицензия — MIT** (выбор владельца: самая простая). Правообладатель —
   «The RosTalk Authors», без личных данных. Проверены зависимости: GPL,
   LGPL и AGPL нет; MPL-2.0 (библиотеки HashiCorp через LiveKit, `cssparser`,
   `selectors`, `option-ext` через Tauri) используется без изменений и
   совместима с поставкой под MIT. Перечень — `THIRD_PARTY_NOTICES.md`.
   Звуки уведомлений — CC0, лицензия лежит рядом с файлами.
5. **Релизы — в публичном репозитории.** `RELEASE_REPO` по умолчанию —
   `v4dikos1/RosTalk` (ADR 0033), поэтому апдейтер, «Хочу свой сервер»,
   `install.sh` и `latest.json` указывают на открытые релизы. Ключ релиза
   Ed25519 и ключ апдейтера minisign прежние.
6. **Подпись кода (Authenticode): пока нет, затем SignPath Foundation.**
   - Античиту подпись user-mode-приложения не нужна: Vanguard, EAC и BattlEye
     не требуют её от программ, которые не загружаются в игру. Она влияет на
     SmartScreen, антивирусы и доверие пользователей.
   - Релизы 0.3.x выходят без Authenticode, с подписанными `SHA256SUMS` и
     minisign-подписью обновлений. README объясняет предупреждение
     SmartScreen и как проверить файл.
   - Цель — бесплатная подпись SignPath Foundation для OSS. Требования:
     OSI-лицензия (выполнено), публичный репозиторий (выполнено),
     автоматическая сборка из этого репозитория (GitHub Actions — отступление
     от ADR 0015, нужен отдельный ADR), MFA у всех участников на GitHub и
     SignPath, страница политики подписи, строка благодарности в релизах.
     Издателем в подписи будет «SignPath Foundation».
   - Запасной путь — OV-сертификат частного лица (например, Certum Open
     Source Code Signing). Microsoft Artifact Signing частным лицам доступен
     только в США и Канаде. EV-сертификат с 2024 года не даёт мгновенной
     репутации SmartScreen, поэтому переплачивать за него незачем.

## Последствия

- Приватная история и материалы приёмки наружу не попадают; публичная
  история короткая — по коммиту на релиз.
- Любой новый приватный файл нужно сразу внести в `exclude.txt`; сканер
  страхует от ключей и личных данных, но не от «просто внутренних» файлов.
- Внешний вклад (PR в публичный репозиторий) переносится в рабочий
  репозиторий вручную (`git am` патча из PR) и возвращается со следующим
  снимком.
- Без Authenticode пользователи видят предупреждение SmartScreen, пока
  подпись не появится; переход на SignPath потребует CI-сборки релизов.
