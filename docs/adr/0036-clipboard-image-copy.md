# ADR 0036. Копирование картинки из чата через WebView2 Clipboard API

- **Статус:** принято (этап P28, playtest-2)
- **Дата:** 2026-11-26
- **Связано:** ADR 0022 (HTTP через loopback-прокси), ADR 0030 (вложения)

## Контекст

Жалоба 10 playtest-2: картинку из сообщения нельзя скопировать и вставить в
Paint — приходится скачивать файл. Нужны два места: миниатюра в ленте и
полноразмерный просмотр. Копироваться должны именно пиксели выбранной
картинки, а не ссылка и не имя файла.

Байты вложения доступны только через авторизованный loopback-прокси ядра
(ADR 0022): сервер проверяет права на канал или личную переписку и отдаёт
файл. WebView не ходит в сеть сам и не получает токен сессии.

Первый вариант писал `CF_DIB`/`PNG` через `OpenClipboard`/`SetClipboardData`.
Ревью отклонило его: это новый Win32 API сверх белого списка
`docs/anticheat.md`, а `OpenClipboard(NULL)` с последующим `EmptyClipboard`
не даёт гарантий `SetClipboardData` по контракту Microsoft. Черновик,
IPC-команда и зависимость `image` удалены.

## Решение

1. **Штатный WebView2 Clipboard API.** UI вызывает
   `navigator.clipboard.write([new ClipboardItem({ "image/png": pngPromise })])`
   прямо в обработчике настоящего клика, до первого `await`. `ClipboardItem`
   по спецификации Clipboard API принимает `Promise<Blob>`, поэтому
   transient activation сохраняется, пока ядро скачивает вложение через
   прокси и WebView перекодирует его в PNG.
2. **Байты только через прокси.** `fetch` идёт на
   `GET /chat/attachments/{id}` loopback-прокси с заголовком
   `X-RosTalk-Proxy-Token` (у `<img>` токен в `?pt=`, потому что картинка не
   может задать заголовок). Права проверяет сервер; новый IPC не нужен.
3. **Потоковый лимит.** `Content-Length` проверяется до чтения; тело читается
   через `ReadableStream` и отменяется, как только сумма превысила 25 МиБ.
   `arrayBuffer` и base64 не накапливают весь ответ.
4. **Лимит декодирования.** Если размеры вложения известны, превышение
   24 Мпикс отклоняется до загрузки. После декодирования клиент сверяет
   фактический размер до выделения canvas и освобождает bitmap и canvas
   после получения PNG или при ошибке.
5. **Отмена при смене сессии.** Смена `proxy.baseUrl`/`proxy.token`,
   размонтирование компонента или более новый клик отменяет прежнюю
   загрузку. Завершение старой операции не меняет состояние новой кнопки.
6. **UI без бесконечной анимации.** Кнопка на время операции `disabled` с
   `aria-busy`; иконка статичная (CONTRIBUTING разрешает только короткие
   `transform`/`opacity`). Успех и ошибки показываются локализованными
   `role="status"`/`role="alert"` строками ru/en.

## Последствия

- Новых Win32 API, IPC-команд, зависимостей и записей в
  `tools/anticheat/allowlist.txt`/`imports-baseline.txt` нет; G7 для этого
  этапа не требуется.
- Paint принимает результат: проверено на релизном клиенте для PNG с
  альфой, JPEG, GIF и WebP, в том числе с задержкой ответа 3 секунды.
- 25 МиБ и 24 Мпикс — клиентские пределы только для копирования; сервер,
  загрузка и просмотр сохраняют прежние лимиты.
- Если WebView2 потеряет активацию на очень медленном канале, пользователь
  увидит локализованную ошибку буфера и повторит действие; отдельного
  нативного fallback нет.
- Текстовое чтение буфера для контекстного меню остаётся прежним.
