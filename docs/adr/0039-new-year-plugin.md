# ADR 0039. Встроенный новогодний плагин и серверный контракт

- **Статус:** принято
- **Дата:** 2026-11-28
- **Решение владельца:** выбран встроенный лениво загружаемый плагин вместо
  скачиваемого пакета; решение делегировано координатору P32.
- **Связанные решения:** ADR 0004, 0019, 0022, 0023, 0026, 0035 и 0038.

## Контекст

Участники одного голосового сервера могут пользоваться разными версиями клиента. Часть пользователей захочет играть только в декабре, остальные продолжат пользоваться чатом. Прогресс должен пережить переустановку клиента и замену соединения. Сервер работает в своём часовом поясе, а участники могут находиться в разных поясах.

## Решение

1. Клиент поставляет игру в подписанном дистрибутиве. В начальной сборке интерфейса находятся небольшой локальный манифест с идентификатором, версией реализации и версией HTTP-контракта, пункт настроек, промо и проверка доступности. Литеральный динамический импорт загружает интерфейс игры, его переводы, стили и рисунки только после включения и подтверждения совместимости сервера. Манифест описывает встроенную поставку. Для внешних пакетов потребуется отдельное решение о подписи, проверке и обновлении.
2. Rust-ядро хранит состояние установки на устройстве в файле настроек. При первом запуске оно равно `absent`; установка переводит в `enabled`, выключение — в `disabled`. Старые настройки получают безопасное начальное значение. При удалении очищаются локальные данные плагина и восстанавливается `absent`. Прогресс привязан к учётной записи данного сервера.
3. После подключения к серверу один короткий авторизованный GET может подтвердить поддержку и окно события. Он нужен для первого предложения установить плагин. Решение «Позже» запоминается для стабильного идентификатора сервера и сезона. Повторяющийся опрос отсутствует. Ошибка старого сервера оставляет чат доступным. Отключение закрывает диалоги и освобождает подписки, запросы, таймеры и игровое состояние. Загруженный JS-модуль может оставаться в кэше WebView до уничтожения окна.
4. Версионированный HTTP API через закреплённое за сессией loopback-соединение обслуживает календарь, награды, активность, размещение игрушек и просмотр ёлки видимого участника. Для каждого метода задан отдельный разрешённый путь. Прокси принимает свой токен в заголовке и сам добавляет серверный bearer. Сервер требует пользовательскую сессию. Внутри чужого профиля выдаются только публичные данные ёлки. Объекты управления, права, сообщения и идентификация пользователя продолжают использовать действующий протокол.
5. Дату, поощрения, стоимость, результат открытия, количество экземпляров и допустимые координаты определяет сервер. Запись в SQLite объединяет проверку условий, списание и выдачу в одну транзакцию. Повтор операции после потери ответа не выдаёт второй приз. Календарный день общий для сервера, в часовом поясе, закреплённом за сезоном. Серверный выключатель прекращает участие и начисление на этом сервере.

## Последствия

Выключенный плагин увеличивает размер дистрибутива и начального интерфейса на небольшой каркас. Проверка сборки и запись сетевой активности должны отдельно показывать размер каркаса и отсутствие загрузки игровых ресурсов до установки. Включённый клиент на старом сервере показывает доступность в настройках и продолжает обычную работу. Отдельный выпуск клиента доставляет изменения игрового кода и рисунков. Изменение правил сервера, которое требует новых ресурсов или меняет смысл полей, требует новой версии контракта.
