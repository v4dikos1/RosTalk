# 0019. Обновление и удаление клиента: настраиваемый источник, подпись, автозапуск

- **Статус:** принято (этап 6.2)
- **Дата:** 2026-11-21
- **Связано:** дизайн 7, ADR 0010 (трей), ADR 0012 (античит), ADR 0015
  (локальная сборка, обновление из UI/вручную)

## Контекст

Дизайн 7 предполагает «установщик для Windows через GitHub Releases,
автообновление Tauri с подписью». ADR 0015 уточняет: хостингового CI и
обязательного GitHub нет, источник обновлений не должен быть зашит в GitHub,
а сборка и приёмка локальные. Для проекта-«для своих» обновления часто лежат
на своём сервере, LAN-шаре или в каталоге, а не в публичном релизе.

Этап 6.2 должен дать: установщик без прав администратора, обновление из UI и
вручную, проверку подписи и версии, `rostalk://`, опциональный автозапуск,
чистое удаление.

## Решение

1. **Источник обновлений задаётся во время работы**, а не при сборке:
   настройка `updateSource` в `settings.json` или переменная
   `ROSTALK_UPDATE_SOURCE` (переменная важнее). Поддерживаются:
   `https://…/latest.json` и абсолютный локальный каталог с `latest.json`.
   HTTP для URL запрещён, чтобы источник нельзя было подменить без TLS;
   офлайн-развёртывание использует каталог.
2. **Формат манифеста — статический JSON Tauri** (`version`, `notes`,
   `pub_date`, `platforms.windows-x86_64.{signature,url}`). Для каталога URL
   пакета — имя файла внутри каталога: клиент переписывает его в `file:` URL
   и не ходит по абсолютным ссылкам из манифеста (нельзя увести загрузку
   наружу).
3. **Подпись — minisign через `tauri-plugin-updater`.** Публичный ключ в
   `tauri.conf.json`; приватный — вне репозитория, по умолчанию
   `%USERPROFILE%\.rostalk\release\rostalk-updater.key`. Подпись проверяется
   перед любым запуском установщика; `requireSignedVersion` связывает
   подписанную версию с объявленной. Каталожный путь (`restore_update`)
   включает эту проверку всегда. Потеря ключа = ручная переустановка у
   пользователей; ключ нужно резервировать.
4. **Установка обновления** — только после явного подтверждения в UI.
   Проверка версии и скачивание не прерывают разговор; установка закрывает
   клиент (ограничение Windows), NSIS перезапускает его. Второй путь — вручную
   скачать установщик и запустить поверх (docs/RELEASE.md).
5. **Установщик — NSIS `currentUser`**, без UAC, служб, драйверов,
   сертификатов, правил файрвола, исключений Defender и упаковщиков.
   `rostalk://` регистрируется в `HKCU\Software\Classes\rostalk` хуком
   установщика и снимается при удалении. Один экземпляр и передача ссылки
   уже работают через `tauri-plugin-single-instance` (этап 2.1).
6. **Автозапуск** — `tauri-plugin-autostart`, значение
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\RosTalk` с
   `--minimized`; по умолчанию выключен. Это белый список античит-гигиены.
7. **Удаление**: на странице подтверждения есть флажок «Удалить данные
   приложения». Если он не отмечен, деинсталлятор спрашивает один раз и по
   умолчанию удаляет личность и настройки; сохранение требует явного «Да».
   Тихий/пассивный деинсталлятор удаляет всегда. Удаляются ключ Credential
   Manager (`rostalk.exe --purge-data`) и `%APPDATA%`/`%LOCALAPPDATA%\
   dev.rostalk.desktop`; запись автозапуска и `rostalk://` снимаются всегда.
8. **Подпись кода Windows** (Authenticode) не обязательна для работы и
   настраивается отдельно (`certificateThumbprint`/`signCommand`). Без неё
   SmartScreen покажет «Неизвестный издатель»; это описано в RELEASE.md.

## Последствия

- Источник можно сменить без выпуска новой сборки; GitHub не обязателен.
- Подпись остаётся единственной границей доверия: TLS не обязателен для
  локального каталога, но пакет без правильной подписи не запускается.
- `tauri-plugin-updater` и `tauri-plugin-autostart` — официальные плагины
  Tauri 2; новых запрещённых крейтов нет (проверяет `make check-anticheat`).
- Клиент не умеет откатываться через апдейтер: манифест должен объявлять
  версию новее установленной. Откат — вручную (RELEASE.md).
- Приватный ключ — единая точка отказа. Его потеря или утечка требует
  нового ключа и ручной переустановки; ключ хранится вне репозитория и
  резервируется.
- Чистое удаление необратимо, если пользователь не выбрал «оставить»;
  экспорт личности нужно предлагать до удаления (RELEASE.md).

## Альтернативы

- **Зашитый GitHub Releases endpoint.** Отклонено: ADR 0015 и требование
  владельца — свой источник.
- **Своя Ed25519-схема вместо плагина.** Больше кода и риска в запуске NSIS;
  плагин уже умеет passive-режим, `/UPDATE`, `/ARGS` и проверку подписи.
- **Локальный HTTP-сервер для каталога.** Потребовал бы разрешить HTTP в
  апдейтере; чтение каталога и `restore_update` проще и не ослабляет
  транспорт.
- **Автозапуск через службу/планировщик.** Запрещено античит-гигиеной и
  избыточно для per-user клиента.
