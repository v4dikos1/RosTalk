# 0016 — Остановка чужого стрима и серверный deafen

## Контекст

Дизайн (4.4) перечисляет права модерации `kick`, `ban`, `move_members`,
`mute_members`, `deafen_members`, а таблица применения прав к медиа описывает
`canPublish` для `speak` и `UpdateParticipant` для серверного mute. Этап 3.1
требует ещё две операции, для которых в дизайне нет отдельного механизма:

- остановить чужой стрим;
- серверный deafen, который пользователь не может снять сам.

Для остановки стрима в таблице прав нет отдельного `stop_stream`, а LiveKit
умеет управлять только публикацией (`canPublish`) и подпиской (`canSubscribe`).

## Решение

- **Остановка стрима** проверяется правом `PERMISSION_MUTE_MEMBERS`: модератор,
  который может выключить микрофон, может и снять чужую демонстрацию экрана.
  Сервер удаляет участника `<user_id>:stream` из комнаты канала, сбрасывает
  флаг `streaming` и рассылает `UserUpdated`. Отдельное право не вводится,
  чтобы не расширять матрицу прав без продуктного решения.
- **Серверный deafen** реализуется через `canSubscribe` в медиа-токене и
  `UpdateParticipant` для уже подключённого участника. В `media.Backend`
  добавлен `SetCanSubscribe`, который сохраняет текущие `canPublish` и
  источники публикации. Клиент не может снять ограничение: оно живёт в SFU,
  а не в UI.
- Серверный mute остаётся как был: `canPublish=false` через `SetCanPublish`,
  флаг `server_muted` в `VoiceState`.
- Оба флага действуют на текущую сессию и забываются при отключении.

## Последствия

- Модератор с `mute_members` может остановить стрим, даже если у него нет
  отдельного права на стримы. Это осознанно: это медиа-модерация, а не
  управление каналами.
- Если позже понадобится отдельное право, его можно добавить аддитивно
  (новое значение `Permission` и проверка вместо `mute_members`) без изменения
  wire-формата; старые клиенты просто не увидят новый пункт.
- `SetCanSubscribe` появился в интерфейсе медиа-плоскости; фейковый бэкенд в
  тестах его записывает, поэтому регрессию видно без запуска LiveKit.
