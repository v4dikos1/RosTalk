# RosTalk UI

React 19 + TypeScript + Vite, running inside the Tauri WebView. Stage 2.2 shows
the real control-plane state from the Rust core; audio arrives in stage 2.3.

## Boundaries

- `src/core/api.ts` is the only interface the UI knows about the Rust core.
  Components import `CoreApi` from there.
- `src/core/tauri/` is the only place allowed to import `@tauri-apps/*`. The
  `no-restricted-imports` rule in `eslint.config.js` enforces it. A browser
  adapter will be added after the MVP.
- `src/core/tauri/bindings.ts` is generated by `tauri-specta` from the Rust
  commands and events. Regenerate it with `make gen-ipc` (Windows) and never
  edit it by hand.
- The UI never talks to the network. All traffic goes through the core IPC; the
  CSP in `tauri.conf.json` allows only the IPC origin.

## State

- `src/store/coreStore.ts` mirrors the core: a `CoreState` snapshot plus
  `StateDelta`s. `applyDelta` is a pure function covered by unit tests. It never
  invents connection or channel state.
- `src/store/appStore.ts` holds only UI-owned preferences (theme, language,
  density, selected channel, open dialogs). Only theme/language/density are
  persisted; the core owns the rest.
- `src/mock/fixtures.ts` and `src/mock/fixtureApi.ts` are a fixture `CoreApi`
  for the component gallery and Playwright. The desktop app selects the Tauri
  adapter; a browser build opts in with `?fixtures=1` (automatic under
  `vite dev`). The main screen never reads the fixtures directly.

## Layout

- `src/components/` — shadcn/ui primitives (`ui/`) and product components
  (channel tree, chat placeholder, streams placeholder, controls, settings,
  connect dialog).
- `src/features/main/` — the main screen; `src/features/gallery/` — the
  development gallery at `#/gallery`, also reachable from Settings → About.
- `src/i18n/` — ru/en resources; every user-visible string goes through `t()`.

## Design tokens

`src/index.css` defines both themes with the same semantic names (`background`,
`surface`, `foreground`, `accent`, `danger`, …). Dark is the default. The accent
is a single ember colour; `success`/`warning`/`danger` are feedback-only.
Dense rows are 30 px (`--row-height`), 28 px in compact mode. Motion is limited
to `transform` and `opacity`, at most 150 ms.

## Tests and screenshots

```sh
npm test                 # Vitest + Testing Library (tree + state reducer)
npm run screenshots      # Playwright, writes docs/assets/stage-2.1/*.png
```

The screenshot run uses the preview build, the fixture adapter and URL overrides
(`?fixtures=1&theme=light&lang=en&view=streams&channel=3`) so it does not depend
on the persisted profile or a running server. Screenshots are committed for
review; CI uploads them as an artifact and does not compare pixels.
